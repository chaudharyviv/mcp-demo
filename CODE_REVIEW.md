# Code Quality Review — MCP Live Demo

**Reviewer:** Claude Code (Opus 5.5) · **Date:** 2026-09-23 · **Commit reviewed:** `83241dc` · **Scope:** review only, no application code changed.

## Overall verdict

The ONTAP mock server and the resize guardrail itself are sound: refusals come before any lookup, nothing writes to disk, and `"synthetic": true` appears on every response. The live path is not demo-ready, though. `requirements.txt` pins a fastmcp version that doesn't exist, so the deploy install fails. Every live tool result crashes on JSON serialisation. Learn and GitHub connect over SSE, but spec §2.3 and the real Learn endpoint use Streamable HTTP. Remote tools are called by their prefixed name. Replay mode hides all of this: the 24 tests pass because they mock or skip exactly these paths, and the "Verified locally" ticks in PROGRESS.md §4 can't be accurate for live runs. The fixes are all small and local. No redesign is needed.

Verification method: read all code against docs/, ran `pytest` (24 passed), and ran direct probes: tool edge cases, `MCPClientManager.call_tool` output types, SSE vs Streamable HTTP against `learn.microsoft.com/api/mcp`, and `pip index versions fastmcp`.

## Do NOT change (looks odd, but correct per the docs)

- **`sys.executable` plus an absolute path to `ontap_mock/server.py`** (mcp_clients.py:29-38). Required by AGENTS §4. Don't replace it with `"python"` or `-m`.
- **A new MCP session per call/turn, and only config in `st.cache_resource`.** The cached manager holds no live session, which is correct per AGENTS §4 and design §2.3. Speed-ups (M3) must keep sessions scoped to one turn.
- **`load_data()` re-reads the JSON on every tool call** (server.py:15). It makes "dataset unchanged" hold by construction. Don't swap it for a module-level cached dict that tools could mutate.
- **Refusal checks run before the volume lookup** (server.py:228-240). A missing or bad `change_id` refuses even for an unknown volume. That order is the guardrail.
- **`"synthetic": true` on refused and error responses too.** Required on every response.
- **The resize tool is "read-only"** (never mutates). This is intentional per spec §2.4, even though it's the "write" tool.
- **Projected % adds the full grow bytes to aggregate used** (thin provisioning ignored). This gives 91.9% ≈ "~92%", as spec §3 expects.
- **Odd byte values in estate.json**, e.g. `vol_ci_cache` footprint `3298534883531` and `aggr_a01` used `20011111625523`. These are deliberate, so footprints sum exactly and `aggr_a01` shows 91.0% (PROGRESS §5 decision). Only the two `snapshot.used` values in H8 need changing.
- **ONTAP tools are not re-prefixed**, since they already start with `ontap_`. Only remote tools get `learn_` or `github_`.
- **`replay/3b_resize.json` has an empty trace.** Correct, because chip 3b must make no tool call.
- **Model `gpt-4o-mini`, temperature 0.2, max 6 iterations, 30 s timeout.** All match AGENTS §4.
- **Presenter mode on by default; the system prompt is loaded from `agent/system_prompt.md` each turn.** Both per spec and AGENTS §5.
